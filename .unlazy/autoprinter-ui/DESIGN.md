# AutoPrinter: спецификация интерфейса

Статус: направление для реализации. Основание — текущие исходники printer-ui;
отрисовка и работа на устройстве не проверены. Аудитория — оператор у принтера.
Главный сценарий: увидеть текущую стадию и следующие запуски, понять блокировку,
приостановить очередь или выполнить разрешённое локальное действие.

## Вход и границы

Единственный новый вход: **Настройки → AutoPrinter**. Добавить группу
`autoprinter` рядом с `cloud`, используя существующий `SettingsSidebarMenu`.
Существующий раздел «Облако» сохраняет AI-настройки. Нижнюю навигацию,
`ScreenId`, dashboard и маршрутизацию не расширять. Новый экран — содержимое
группы настроек; это не модальное окно и не новый рекламный экран.

Внутри группы две явно подписанные кнопки выбора: **Очередь / Связь**.
Использовать существующее оформление `segmented-toggle-btn`, выбранность
передавать через `aria-pressed`; не объявлять ARIA tabs без соответствующей
клавиатурной модели. Переключение меняет только локальное представление.

Панель получает валидированные DTO, состояния команд и callbacks через props.
Она не делает fetch/polling, не выводит разрешения из доступности кнопки,
не подменяет общий pure guard и не создаёт второе состояние runtime.
Названия DTO и точные команды определяет общий CONTRACT, не этот документ.
Результат локального действия подтверждается явным `action_result` core;
один HTTP-ответ без такого подтверждения не означает успешное действие.

## Композиция 960×544

Сохранить текущую оболочку: нижняя навигация 84px, отступ content-grid 8px,
левое меню Settings 190px, промежуток 8px, внутренние поля правой области 16px.
Рабочая область правой панели получается примерно 710×408px; размеры зависят
от существующих рамок. Использовать доступную высоту grid, не растягивать canvas.

| Зона | Состав и приоритет |
| --- | --- |
| Шапка, 56px | «AutoPrinter» слева; «Очередь / Связь» справа. Обе кнопки не ниже 56px |
| Статусы, около 40px | Три отдельные колонки: «Принтер», «TreeD», «Стол». Под каждой короткое текстовое состояние; источник принтера — Moonraker |
| Содержимое, оставшаяся высота около 208px | Текущий запуск и ближайшие два запуска либо содержимое вкладки «Связь» |
| Нижняя область, около 80px | Основное действие высотой 56px и короткое пояснение области действия; всегда видима |

Между зонами 8px. Содержимое не должно вытеснять нижнюю область и перекрывать
навигацию. Для новой группы задать локальный layout без вертикальной прокрутки
всей правой панели; не менять поведение остальных групп Settings.
Левое меню сохраняет разрешённую вертикальную прокрутку. Desktop/mobile
breakpoints и portrait layout в эту задачу не входят.

### Очередь

- Верх содержимого: подпись «Сейчас», идентификатор запуска и стадия крупнее
  метаданных. Текущая стадия — семантический label из общего domain package.
  Если название файла отсутствует, показывать «Запуск …» с реальным ID.
  Владельца, заказчика, название модели, время завершения и процент не выводить
  из косвенных признаков. Не приписывать Moonraker-файл запуску без связи в DTO.
- Ниже заголовок «Следующие» со счётчиком только из DTO и до двух строк по 56px.
  Каждая строка: порядковый номер, реальный ID/доступное название и состояние.
  Строки read-only; действия сортировки, удаления, перетаскивания не добавлять.
  Если есть ещё элементы, подпись «Показаны ближайшие 2 из N» допустима только
  при подтверждённом общем количестве. Полную очередь этот экран не обещает.
- Длинные имена: максимум две строки; полное значение доступно через отдельную
  кнопку сведений только при необходимости и с зоной 48×56px. Не полагаться
  на hover/title. Идентификатор остаётся доступен в accessible name.
- Внизу одна кнопка **Приостановить очередь** либо **Продолжить очередь**.
  Пояснение: «Текущая печать продолжится» для pause; для resume — фактическая
  причина блокировки или «Следующий запуск проверит условия старта».
- Текущая печать остаётся под контролем существующего dashboard. При наличии
  активной печати рядом допустима нейтральная кнопка **К печати**, вызывающая
  существующий выбор `dashboard`. Она не отправляет команду устройству.
  Не дублировать здесь «Стоп» и «Пауза печати»: существующие локальные controls
  должны сохранять доступность при потере TreeD или AutoPrinter.
- Pending/error/uncertain команды отображать постоянно в области содержимого,
  при необходимости вместо строк будущих запусков; текущая стадия и footer
  остаются видимы. Не добавлять ошибку ниже экрана и не прятать её в toast.

### Связь и локальные действия

- Показывать привязку устройства отдельно от соединения TreeD. «Привязан»
  не означает «В сети». Владельца показывать только если соответствующее поле
  явно присутствует в разрешённом DTO; иначе «Данные владельца недоступны».
- **Получить код привязки** открывает компактный диалог с реальным кодом,
  сроком действия и состоянием запроса. Код — JetBrains Mono, 32px, без
  маскирующих декоративных точек. TTL — из срока core, а не придуманная константа.
  Не создавать QR-код, ссылку или адрес кабинета без явного API-контракта.
- По истечении TTL код перестаёт считаться действующим; текст «Код истёк» и
  разрешённая кнопка «Получить новый код». Не обещать успешную привязку после
  самого создания кода. Не сохранять код в логах или локальном постоянном хранилище.
- **Отвязать устройство**, **Повторить проверку стола** и другие переданные
  локальные команды показывать только при наличии подтверждённого callback
  и guard. Не придумывать команды для заполнения пространства. Для необратимого
  или прерывающего действия нужен существующий pattern подтверждения.
- Если локальных действий больше двух, раскрывать отдельное представление
  внутри этой группы с явным «Назад»; не уменьшать touch-targets и не прятать
  критичные CTA под прокруткой. Конкретный набор задаёт CONTRACT.

## Состояния и честность данных

| Данные/событие | Текст и поведение |
| --- | --- |
| Первая загрузка | «Получаем состояние AutoPrinter»; значения «—», команды недоступны; обычная навигация доступна |
| Старый core/endpoint отсутствует | «Эта версия системы не поддерживает AutoPrinter»; не рисовать пустую очередь и нулевые счётчики |
| Core недоступен | «Нет связи с AutoPrinter»; сохранённые значения помечены «Последние данные»; команды, требующие актуального core, недоступны |
| `enabled=false` | «AutoPrinter выключен в системе»; не заменять на «Очередь пуста» и не давать неподключённый переключатель включения |
| Свежая пустая очередь | «В очереди нет запусков» только после валидного ответа с пустым списком/нулевым подтверждённым количеством |
| Список не поддерживается, есть только counts | Показывать известный счётчик и «Список запусков недоступен в этой версии»; не синтезировать строки |
| Принтер доступен, TreeD offline | «Принтер: подключён», «TreeD: нет связи»; локальная печать и её cancel не зависят от облачной связи |
| Стол occupied | «Стол занят» и причина блокировки старта; нет кнопки «Всё равно печатать» |
| E0 unknown / ошибка / stale | «Состояние стола неизвестно»; не превращать отсутствие данных в empty |
| `empty` без действительной qualification | «Пустота стола не подтверждена»; запуск заблокирован |
| `empty` с действительной qualification по DTO/guard | «Стол свободен»; это отображение факта, а не самостоятельное разрешение старта |
| Pending команды | Кнопка с названием операции и «…», повторная отправка недоступна; не менять итоговое состояние оптимистично |
| Ответ потерян / uncertain | «Результат команды пока неизвестен»; сохранённый статус не выдавать за подтверждение; не делать автоматический повтор mutation |
| Ошибка команды | Краткая причина рядом с действием; остаётся видимой до следующего осмысленного действия/подтверждения; retry только по контракту |

Свежесть, qualification, разрешение старта и command guards приходят из общего
слоя. В UI не вычислять ML-confidence thresholds, не считать один текст `empty`
достаточным и не добавлять ручное «Подтвердить пустой стол» как обход проверки.
Старт файла вне AutoPrinter тоже сохраняет общий запрет E0, если он предусмотрен
контрактом. Пауза очереди и пауза текущей печати — разные команды и состояния.

## Визуальные токены и доступность

Использовать `src/styles/foundation.css` и итоговые overrides `ui-kit.css`:
монохромные `--color-background`, `--color-block-surface`, существующие border
tokens. Одна внешняя граница правой области; строки разделять тонкими линиями
или интервалами, не оборачивать каждую подпись в карточку. Новым панелям radius
`--radius-panel`, контролам `--radius-control`. Новые цвета, тени, glow не нужны.

Заголовок 22px; стадия 20px; текст и кнопки 16px; метаданные 14px. Вес 400.
Nothing Font — только акцентная надпись; функциональные статусы, код, кнопки и
ошибки — `--font-family-ui`. Красный обозначает выбранность/опасность, состояние
дублируется словами. Причины блокировки использовать с читаемым основным или
вторичным текстом; не снижать opacity всей области вместе с важным объяснением.

Все новые кнопки ≥48×56px, расстояние ≥8px. `button`, `disabled`, видимая подпись;
декоративные `IconMask` не дублируют доступное имя. Обновления состояния — одна
уместная `role=status`/polite область без объявления каждого тика TTL и каждого
poll. Ошибка операции может иметь `role=alert`, без повторного объявления на
каждом рендере. Порядок Tab соответствует чтению; обновление DTO не переносит фокус.

Диалоги используют `useModalFocus`, `role=dialog`, `aria-modal=true`,
`aria-labelledby`. Фокус сначала на безопасном «Назад/Закрыть» с
`data-modal-initial-focus`; Tab остаётся внутри, Escape закрывает, после закрытия
фокус возвращается на trigger. Закрытие окна не означает отмену уже отправленной
команды: её статус хранится в runtime и остаётся виден после возврата. Ширина
диалога ≤640px, высота ≤512px, поля 16px; footer 56px без перекрытия клавиатурой.
Уменьшение движения — существующий `prefers-reduced-motion`, обычный control
transition — `--motion-control`. Новые анимации входа не требуются.

## Контур реализации для worker

| Путь | Изменение |
| --- | --- |
| `src/settings/config.ts` | Новый `SettingsGroupId` и элемент существующего меню |
| `src/settings/SettingsPage.tsx` | Props AutoPrinter и ветка нового feature-компонента; сохранить Cloud/AI |
| `src/settings/SettingsContainer.tsx` | Передать props без собственного polling |
| `src/autoprinter/AutoPrinterPanel.tsx` (предлагаемый новый файл) | Только view, выбор двух представлений, диалоги и callbacks |
| `src/autoprinter/autoprinter.css` (предлагаемый новый файл) | Локальная композиция фиксированного canvas и существующие tokens |
| `src/App.tsx` и текущее composition wiring | Подключить единый runtime snapshot/actions к settings; не переносить сюда markup панели |

Общий DTO и runtime/client реализуются назначенными владельцами. Перед записью
нового `src/autoprinter` worker обязан проверить его актуальные локальные правила.
`AppScreenContent`, dashboard и shared primitives не требуют визуального редизайна.

Проверяемые критерии при реализации: нет fake queue/owner/file/QR; unsupported,
disabled и offline различимы; E0 unknown и qualification=false не показывают
готовность; очередь pause не вызывает print pause; uncertain не превращается
в success; native cancel работает без TreeD; ошибки остаются в пределах canvas;
диалоги и новые controls сохраняют touch/focus контракт. Наличие этих критериев
не является разрешением на browser, build, hardware или расширенные проверки.
