Гладкие контурные SVG и прежняя типографика внутренних экранов не являются актуальным заданием. Текущие PNG каталога/папки и JPG высоты просмотрены при подготовке нового ТЗ.

Назначение: дополнение текущих экранов без изменения команд, стадий, guards и фактических источников состояния. Проверены текущие `CalibrationProcedures.tsx`, `calibrationProcedures.css`, `EddyCalibrationScreen.tsx`, `eddyCalibration.css`, `AGENTS.md` и `docs/00_FOUNDATION.md`. Использован `ui-ux-pro-max` и контракт designer из `astra-orchestrator/references/design.md`. Рендер и PID-референс дизайнером не просмотрены; визуальное сходство с PID не заявляется. Визуальная приёмка остаётся у основного агента.

## Основной каталог и папка

- Основной каталог: шесть карточек, три колонки и два ряда. Порядок: «PID-калибровка», «Eddy», «Шейпер и ADXL»; «Подача экструдера», «Профиль материала», «Сервисная телеметрия».
- Eddy — явно папка: рисунок датчика внутри контура папки, подпись «Датчик и стол», отдельная строка «4 раздела →». Нажатие открывает папку, не отправляет команду.
- В папке четыре карточки, две колонки и два ряда: «Калибровка Eddy», «Винты стола»; «Карта стола», «Первый слой». Первая открывает существующий обзор десяти процедур, остальные ведут в существующие процедуры напрямую.
- У папки заголовок «Eddy», над ним или рядом текст принадлежности «Калибровки / Eddy». Слева кнопка «← Назад» размером 112×56, возвращающая основной каталог. В корневой шапке: «Калибровки» и «Выберите процедуру».
- При возврате из любой операции Eddy показывать папку Eddy; из её обзора — также папку. В процедуре сохранить «К обзору» для перехода к десяти подэтапам. Верхнюю кнопку переименовать из «К списку макросов» в «В папку Eddy». Не оставлять возврат в общий каталог при подписи, обещающей папку.
- Сохранять выбранную папку на уровне существующего родителя, если `CalibrationProcedures` размонтируется при открытии Eddy: локальное состояние размонтируемого компонента не обеспечит правильный возврат. Не вводить router или историю маршрутов.

## Композиция на 960×544

Расчёт выполнен для доступной области 960×452 над нижней навигацией. Не прибавлять указанный padding повторно к уже существующему внешнему отступу: это итоговый отступ содержимого относительно доступной области.

- Каталоги: внешний padding 16; шапка 56; промежуток 16; сетка 348 по высоте, межкарточные интервалы 16. Корневые карточки примерно 299×166, в папке — 456×166. Использовать `minmax(0, 1fr)`, без фиксированной ширины самой карточки.
- Карточка: одна внешняя рамка, padding 16, внутри верхняя строка «рисунок + текст» и нижняя строка состояния/назначения. Корневое превью 80×80; в папке 96×80. Между рисунком и текстом 16. Заголовок 20px/400, максимум две строки; короткое пояснение 14px, максимум две строки; нижняя подпись 14px. Нет отдельной рамки вокруг SVG, дублированного заголовка или маленькой вложенной кнопки.
- Пояснения основного каталога: «Сопло и стол», «Датчик и стол», «Резонансы и датчик», «Длина подачи», «Тесты печати», «Данные принтера». Полные пояснения остаются на экранах процедур.
- Внизу папки/карточки калибровки можно показывать существующий `completedRequiredCount/5` с подписью «Обязательные этапы», только в одном месте. Не распространять этот общий счётчик на карточки винтов, карты и первого слоя как их собственный результат.
- Цвета, поверхности, рамки, радиусы, фокус и pressed-состояния брать из Foundation. Все карточки — целиком одна кнопка с visible label. SVG рядом с текстом `aria-hidden="true"`, `focusable="false"`. Статус всегда выражен текстом, не только цветом.

## Превью

Один компонент с точным закрытым набором рисунков, без библиотеки и новых зависимостей:

```tsx
type CalibrationPreviewKind =
  | 'pid' | 'eddyFolder' | 'eddy' | 'shaper' | 'extruder' | 'material' | 'service'
  | 'driveCurrent' | 'height' | 'temperature' | 'z0' | 'offsets' | 'accuracy'
  | 'screws' | 'mesh' | 'xyOffset' | 'firstLayer'

type CalibrationPreviewProps = {
  kind: CalibrationPreviewKind
  className?: string
}
```

SVG `viewBox="0 0 96 80"`, общий контур 2px, `fill="none"`, цвет основного рисунка `currentColor` через существующий цвет текста. Крупная простая силуэтная схема с 2–4 осмысленными деталями. При диагностическом размере 32–40px оставлять различимый силуэт; не рисовать текст, цифры, тонкую штриховку или миниатюрные приборные шкалы.

| kind | Изображение |
| --- | --- |
| pid | Сопло над горизонтальной плитой; рядом термометр. |
| eddyFolder | Контур папки с выступом; внутри датчик над плитой. |
| eddy | Датчик, катушка в его нижней части и плита под ним. |
| shaper | Печатающая головка и две двунаправленные горизонтальные стрелки вибрации по бокам. |
| extruder | Два подающих ролика, нить между ними, нижняя стрелка подачи. |
| material | Катушка нити рядом с небольшим печатным образцом. |
| service | Плата с тремя разъёмами и датчиком; без выдуманных показаний. |
| driveCurrent | Крупная катушка и разъём питания. |
| height | Датчик над плитой, вертикальная размерная стрелка между ними. |
| temperature | Датчик и крупный термометр. |
| z0 | Сопло касается линии поверхности; метка точки контакта. |
| offsets | Сопло над плитой, два уровня и вертикальная стрелка между ними. |
| accuracy | Датчик и две стрелки повторного движения к одной отметке поверхности. |
| screws | Плита с четырьмя винтами и стрелка поворота у одного винта. |
| mesh | Плоская перспектива стола с регулярной сеткой 3×3; никакого рельефа, тепловой карты или вымышленных измерений. |
| xyOffset | Вид сверху: сопло и датчик, между ними ортогональные размерные стрелки X/Y без мелкого текста. |
| firstLayer | Сопло, оставляющее на плите три параллельные дорожки. |

Красный — семантический сигнал выбора/активности или ошибки в карточке через существующие токены. Статическое превью нейтрально; при выбранной/активной карточке допускается красная небольшая отметка измеряемого места, согласованная с текстовым состоянием. Не окрашивать каждый рисунок красным ради украшения, не имитировать готовность датчика. Превью не принимает snapshot, числовые данные или статус и не изображает график результата. Реальные графики остаются в соответствующих процедурах.

## Обзор десяти процедур Eddy

Сохранить существующие десять кнопок в сетке 5×2 и их фактические status/value. Удалить только дублирующий `ol` блока «Полная настройка»: десять кнопок уже показывают весь набор. Сохранить отдельную кнопку «Начать последовательность» высотой 56 внизу; не менять её обработчик и доступность.

- При текущем padding 8: header 64, gap 8, grid 300, gap 8, footer 56; общая высота 452. Каждая карточка около 182×146, gap 8. Не оставлять список последовательности рядом с CTA.
- Диагностическая карточка: padding 8; верхняя строка минимум 40 с SVG 32×32 слева и названием 16px справа (до двух строк); ниже отдельные status 12px и value 14px, интервалы 4. SVG не заменяет статус или показания. Для названия «Компенсация температуры» использовать компактное «Температура» в карточке; полный заголовок сохраняется внутри процедуры.
- Числовые фактические значения оставлять числами с единицами. Длинный результат повторяемости допустимо кратко описать на карточке как «Есть результат» только если полный исходный результат остаётся доступен сразу после открытия процедуры. Нельзя обрезать предупреждение и выдавать неизвестное состояние за готовность.
- Отдельные длинные ошибки/неопределённое состояние не втискивать в карточки: сохранить существующий видимый блок сообщения, уменьшив область сетки либо перейдя к разрешённой вертикальной прокрутке сообщения. Аварийные и заблокированные состояния важнее декоративного превью. Проверить фактическое размещение на рендере.

## Приёмка

Root: видны все шесть превью, заголовки и отдельная папка Eddy. Folder: видны принадлежность, доступный возврат и четыре карточки. Overview: десять карточек, SVG не похожи на фактические графики, статус и значение различимы, CTA не перекрыт нижней навигацией. Возврат из Eddy приводит в папку; guards не изменены. Порядок Tab совпадает с порядком чтения; фокус не обрезан. Проверить обычное, unknown/disabled и длинное сообщение при фактическом рендере.

Дизайнер не менял production-код и не запускал runtime, браузер, тесты или Git. Основной риск — фактическая высота shell и длинные device-backed сообщения; расчёт размеров не заменяет визуальную проверку.
