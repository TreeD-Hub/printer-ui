# Независимый экран обновления TreeD

Этот документ фиксирует целевое разделение экранного сеанса принтера и заменяемого web UI. Это проект следующего этапа, а не описание уже работающей функции.

## Подтверждённое ограничение текущего runtime

Сейчас `treed-shell.service` одним запуском владеет `xinit` на `:0`, HTTP-сервером локального bundle и Chromium kiosk. Перезапуск этой службы останавливает браузер и X-сеанс. Установленный loader также вызывает `plymouth quit --retain-splash` перед запуском UI. Поэтому полноэкранный React-экран может наблюдать операцию, пока загружено приложение, но не может оставаться видимым при перезапуске его службы или browser/runtime.

Активная Plymouth-тема показывает логотип и boot-прогресс. В проекте пока нет подтверждённого runtime-контракта, который после завершения загрузки заново поднимает Plymouth, получает состояние обновления и безопасно делит физический дисплей с X. Использовать поздний Plymouth splash как уже проверенный экран обновления нельзя.

## Целевое разделение

```mermaid
flowchart LR
  O[Root-служба обновления] --> S[/var/lib/treed-update/state.json]
  S --> G[Локальный display gateway]
  G --> P[Постоянная splash-страница]
  G --> U[/ui bundle/]
  X[Постоянный X-сеанс и kiosk] --> G
  P -->|операция активна или требует результата| P
  P -->|нет незавершённой операции| U
```

Один системный display-сеанс владеет физическим X/VT и kiosk-browser на протяжении работы устройства. Заменяемый TreeD UI становится содержимым этого сеанса: его bundle можно остановить, заменить и снова запустить, не закрывая X или браузер.

Постоянный локальный gateway раздаёт два ресурса на loopback:

- неизменяемую страницу состояния TreeD, поставляемую вместе с `printer-core`, с существующим `watermark.png`;
- текущий bundle UI по отдельному пути.

Возможное разбиение systemd-контуров: `treed-display-session.service` владеет X/VT и kiosk-browser; `treed-display-gateway.service` обслуживает неизменяемую страницу, статус и сменные UI-файлы. Названия предварительные. Gateway работает от отдельного непривилегированного пользователя с read-only доступом только к одному snapshot-файлу. Он не получает root-команд и не запускает обновлятор.

Kiosk всегда открывает постоянную страницу gateway. Она читает read-only snapshot root-службы обновлений и показывает экран состояния, пока операция активна. При отсутствии активной операции страница открывает UI bundle. После терминального результата экран остаётся видимым до действия «Продолжить»; подтверждение хранится отдельно от root-owned operation record и относится только к его `operationId`.

Статусы и этапы берутся из сохранённой операции (`queued`, `validating`, `downloading`, `installing`, `restarting`, `verifying`, `rolling_back` и терминальный результат). Полоса процентов показывается только при наличии измеренного `progress`; иначе экран сообщает этап и использует неопределённый индикатор. Root-служба остаётся источником истины. UI и gateway не записывают в системное состояние.

React-клиент запрашивает Screen Wake Lock на время активной операции, если браузер его поддерживает. Это помогает при видимой вкладке, но не гарантирует системный запрет сна. Для физического принтера root runtime должен дополнительно удерживать `systemd-inhibit` от начала операции до terminal state; gateway/display-unit проверяет видимость итогового экрана. Восстановление inhibit после перезагрузки определяется сохранённым busy-state.

Во время перезапуска web UI gateway и kiosk остаются доступны. При перезагрузке устройства Plymouth отвечает только за раннюю загрузку; после старта системы постоянная страница читает сохранённое состояние и восстанавливает экран операции до возврата к UI. React и browser storage не считаются механизмом восстановления после reboot.

## Владение и точки передачи

| Часть | Владелец | Контракт |
| --- | --- | --- |
| Операция, очередь, журнал, решение об откате | root-служба обновлений `printer-core` | Атомарный root-owned state; snapshot доступен только для чтения локальному gateway и Moonraker API |
| A/B-запись и health check | platform/loader `printer-core` | Выбранный слот подтверждается только после health check; при ошибке bootloader загружает предыдущий слот |
| X/VT и Chromium kiosk | постоянная display-служба `printer-core` | Сеанс не принадлежит сервису, который раздаёт обновляемый UI |
| Gateway, splash HTML/CSS/JS и логотип | `printer-core` | Постоянные файлы вне UI release bundle; gateway читает snapshot и обслуживает UI по отдельному пути |
| Пользовательский экран и API | `printer-ui` | Клиент запускает запрос, опрашивает operation/status и показывает тот же этап/результат внутри UI, когда UI доступен |

Точки передачи:

1. UI отправляет `requestId` и целевую версию Moonraker API.
2. Root-служба принимает запрос, сохраняет операцию и публикует её локальный snapshot.
3. Постоянная страница замечает операцию и закрывает/заменяет только UI-содержимое; X и gateway продолжают работать.
4. Обновлятор записывает неактивный слот или bundle и обновляет состояние операции.
5. Проверка подтверждает новую версию либо root-служба/bootloader возвращают предыдущую; terminal outcome сохраняется.
6. Gateway показывает итог и возвращает пользователя к UI после явного действия.

## Порядок внедрения

1. Зафиксировать владельца X/VT на поддерживаемой плате и исключить параллельное открытие второго X server.
2. Выделить постоянную display-службу из текущего `treed-shell.service`; оставить в заменяемой части только доставку/подачу UI bundle.
3. Добавить root-owned read-only status endpoint gateway и отдельную страницу состояния вне bundle UI; использовать существующий брендовый asset.
4. Подключить выбор страницы к durable operation state с нейтральным экраном при недоступности API и состоянием восстановления после reboot.
5. Подключить handoff updater к тем же стабильным operation IDs, фазам и терминальным кодам, что и Moonraker API.
6. Только после проверок на целевой плате включить экран в установочный образ и переключить loader на новую service ownership схему.

## Критерии приёмки на целевом устройстве

- Выключение или перезапуск UI HTTP/app-процесса не закрывает kiosk, X-сеанс и splash.
- Смена UI bundle не уводит экран в ошибку браузера и не показывает пустой экран.
- Потеря Moonraker-соединения не выглядит как отмена; локальный root snapshot продолжает показывать актуальный этап.
- Перезагрузка во время операции возвращает экран состояния после старта OS; A/B bootloader выбирает подтверждённый либо резервный слот.
- Screen Wake Lock используется только как клиентская помощь; systemd inhibitor удерживается и освобождается согласно durable operation state.
- Успех, ошибка и rollback остаются видимыми до действия пользователя и используют русский текст.
- Touch controls помещаются в `960x544`; прогресс не выдумывается, кнопки доступны без hover.
- Проверены реальные комбинации платы, HDMI/разрешения, Xorg/VT, Plymouth renderer, браузера и восстановления загрузки. Симуляция в браузере не заменяет эти проверки.

## Текущее состояние

В `printer-ui` реализуется экран операции внутри React UI и восстановление наблюдения через Moonraker. Независимый display gateway, постоянный X-сеанс и handoff после остановки browser/runtime здесь не реализованы. На текущем checkout нельзя заявлять, что экран переживает перезапуск `treed-shell.service`; аппаратные проверки целевого display lifecycle не проводились.
